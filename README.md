# Control Old 2026 Archive

2026 赛季 ROBOCON 控制代码归档仓库，包含 R1、R2 两台机器人的相关代码和资料。

> 当前仓库在上传、整理和安全审查完成前应保持私有。公开不代表已完成许可证或安全审查。

## 项目组织

项目通常包含上层与下层：

- 上层主要负责机器人的各种动作和任务功能。
- 下层主要负责机器人的导航相关功能。

这不是固定的人员分工。每台机器人、每个模块的参与人数和负责人，以 2026 赛季实际安排为准；同一成员可能负责多个模块，也可以跨 R1/R2 或上下层协作。

## 建议目录

```text
R1/
  upper/       R1 上层动作与任务功能
  lower/       R1 下层导航相关功能
  docs/        R1 接口、标定与联调记录
R2/
  upper/       R2 上层动作与任务功能
  lower/       R2 下层导航相关功能
  docs/        R2 接口、标定与联调记录
shared/        两台机器人共用且已确认可复用的模块
system/        R1/R2 协同、场地流程与全局说明
tools/         构建、部署和诊断工具
```

实际上传代码后，应以真实目录和当年分工为准，不要为了匹配示例而改动原项目。

## 每部分需要记录

- 实际参与成员及职责范围
- 硬件平台、控制器和关键外设
- 操作系统、工具链、ROS/依赖版本
- 上下层接口、单位、坐标系、频率和超时策略
- 编译、烧录、启动、标定与联合调试方法
- 对应的最终比赛版本或 Git 标签
- 已知问题、现场注意事项和维护状态

## 公开前检查

- [ ] 已扫描当前文件和完整 Git 历史中的密钥、密码与个人信息
- [ ] 已确认第三方 SDK、库、模型和比赛资料允许再分发
- [ ] 已确定并添加合适的 `LICENSE`
- [ ] 已移除构建产物、大型日志和无用二进制文件
- [ ] R1/R2 的上下层版本和接口能够正确对应
- [ ] 关键版本已由当季相关成员或负责人复核
- [ ] 仓库公开后设置为只读 Archive，或明确后续维护方式

发现敏感信息时，不要只删除当前文件；应立即轮换相关凭据并清理 Git 历史。
